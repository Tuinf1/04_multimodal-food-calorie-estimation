Сдача репозитория с проектом на ревью
Вам нужно сдать на ревью два артефакта: репозиторий в GitHub и Jupyter Notebook. Ревьюер проверит и то, и другое и даст обратную связь по всему проекту. В этом уроке сдайте на ревью первый артефакт проекта — репозиторий в GitHub.
Перед сдачей проекта пробегитесь по чек-листу и доработайте проект, если нужно. Если всё выполнено — смело сдавайте! 


Чек-лист для сдачи проекта

Выполнены все шаги проекта. Получены такие результаты: 
Этап проекта	Результат
1. Проведение EDA	- Проведён EDA.
- Написаны выводы о подходах к решению задачи.
2. Реализация пайплана обучения	- Созданы Python-файл или файлы с воспроизводимым кодом обучения.
- Все результаты воспроизводятся путём вызова train с передачей конфигурационного файла.
3. Обучение модели	- Есть артефакт обученной модели
4. Валидация качества	- Выполнен инференс обученной на этапе 3 модели.
- Визуализированы топ-5 самых тяжёлых примеров для модели из test набора.
- Описаны возможные причины низкого качества на этих примерах.
5. Оформление проекта	- Код запуска обучения и все подводящие функции оформлены в .py файлах.
- Само обучение и EDA выполнено в Jupyter Notebook'е.
- Код ноутбука разделён на смысловые блоки.
- Код легко читать.
- Все ячейки выполняются по порядку.
- Выводы ноутбука сохранены в отправке на проверку.


Как сдать на ревью репозиторий в GitHub
Выполните шаги: 
Перейдите во вкладку «Ревью».
Прикрепите свой репозиторий в формате .zip.
Затем перейдите в следующий урок и сдайте на ревью второй артефакт проекта — Jupyter Notebook. Проект считается переданным на ревью, когда прикреплены оба артефакта.
