## 1. Цель проекта

Создать воспроизводимую мультимодальную DL-модель, которая оценивает общую калорийность блюда по:

- фотографии;
- списку ингредиентов;
- общей массе порции.

Основная метрика качества - `MAE` на тестовой выборке.

Целевой результат:

```text
MAE < 50 ккал
```

Кроме модели, проект должен содержать EDA, воспроизводимый пайплайн обучения, сохранённый checkpoint, инференс и анализ пяти самых больших ошибок.

## 2. Принципы работы

Чтобы быстрее получить хороший и объяснимый результат, будем двигаться от простого к сложному:

1. Проверим качество данных.
2. Создадим простые baseline-модели.
3. Реализуем и проверим нейросетевой пайплайн на небольшом объёме данных.
4. Постепенно добавим изображение, текст и массу.
5. Будем сравнивать эксперименты только по validation-выборке.
6. Используем test только для итоговой оценки выбранной модели.

За один эксперимент меняем только один существенный компонент. Для каждого запуска сохраняем конфигурацию и результаты.

## 6. Этап 3. Подготовка выборок

Исходный `test` не используется для подбора модели.

Из исходного train создаём:

- внутренний train - примерно 85-90%;
- validation - примерно 10-15%.

Разделение должно быть воспроизводимым через фиксированный `random_state`.

### Проверки

- Сходство распределений целевой переменной.
- Сходство распределений массы.
- Возможные дубликаты изображений.
- Возможные одинаковые или почти одинаковые блюда в разных частях.
- Отсутствие утечки test в обучение и подбор параметров.

### Критерий готовности

Все эксперименты можно честно сравнивать по одной validation-выборке.

## 7. Этап 4. Подготовка признаков

### Ингредиенты

Создадим словарь:

```text
ingredient_id -> ingredient_name
```

Преобразуем техническую строку:

```text
ingr_0000000122;ingr_0000000026
```

в осмысленный текст:

```text
salmon, zucchini
```

Одинаковая функция преобразования используется для train, validation и test.

### Масса

`total_mass` используется как отдельный числовой признак. Проверим:

- стандартизацию;
- преобразование `log1p`;
- обработку аномальных значений.

Параметры преобразований рассчитываются только на train.

### Изображения

Базовая обработка:

- чтение `data/images/<dish_id>/rgb.png`;
- преобразование в RGB;
- изменение размера;
- нормализация под предобученный image encoder;
- преобразование в tensor.

Безопасные аугментации для train:

- горизонтальное отражение;
- небольшое вращение;
- умеренное изменение яркости и контраста;
- небольшой shift и scale.

Для validation и test используются только resize и нормализация.

## 9. Этап 6. Dataset и DataLoader

В `scripts/dataset.py` реализуем:

- загрузку подготовленной таблицы;
- открытие изображения по `dish_id`;
- применение аугментаций;
- токенизацию текста;
- преобразование массы и target в tensor;
- обработку ошибок чтения;
- DataLoader для train, validation и test.

Один объект датасета должен возвращать все необходимые данные и служебные поля:

```python
{
    "image": image_tensor,
    "input_ids": input_ids,
    "attention_mask": attention_mask,
    "mass": mass_tensor,
    "target": target_tensor,
    "dish_id": dish_id,
}
```

Перед полным обучением проверим формы и типы всех tensor на одном batch.

## 10. Этап 7. Мультимодальная модель

Модель состоит из трёх веток.

### Ветка изображения

Предобученный encoder из `timm`. Первый кандидат - лёгкая модель уровня EfficientNet-B0 или ConvNeXt Tiny.

### Ветка текста

Компактный предобученный transformer для английских названий ингредиентов.

### Ветка массы

Нормализованная масса проходит через небольшой MLP.

### Объединение признаков

```text
image encoder -> image projection
                                \
text encoder  -> text projection -> concatenation -> fusion MLP -> 1 число
                                /
mass          -> mass encoder
```

Финальный слой:

```python
nn.Linear(hidden_dim, 1)
```

Функция активации после последнего слоя не используется.

### Варианты target

Сравним два подхода:

1. Прямое предсказание `total_calories`.
2. Предсказание энергетической плотности с последующим умножением на массу.

Оба варианта оцениваются по MAE общей калорийности.

## 11. Этап 8. Пайплайн обучения

Главная функция:

```python
history = train(config)
```

Она должна выполнять:

1. Установку seed.
2. Загрузку и разделение данных.
3. Создание датасетов и DataLoader.
4. Создание модели.
5. Создание loss, optimizer и scheduler.
6. Обучение по эпохам.
7. Validation после каждой эпохи.
8. Сохранение лучшего checkpoint по validation MAE.
9. Early stopping.
10. Сохранение истории обучения.
11. Возврат метрик и путей к артефактам.

### Основные настройки

- Loss - `nn.L1Loss()`.
- Главная метрика - MAE.
- Дополнительная метрика - RMSE.
- Начальный batch size - 4.
- Mixed precision для экономии памяти.
- Gradient clipping для устойчивости.
- Разные learning rate для предобученных и новых слоёв.

### Оптимизатор

В optimizer обязательно включаются:

- image encoder;
- text encoder;
- image projection;
- text projection;
- mass encoder;
- fusion layers;
- regression head.

Замороженные параметры в optimizer не передаются.

## 12. Этап 9. Проверка пайплайна

До долгого обучения выполняем три теста.

### Тест 1. Один batch

- Данные загружаются без ошибок.
- Размерности tensor правильные.
- Forward pass завершается.
- Loss вычисляется.
- Backward pass завершается.

### Тест 2. Переобучение маленькой выборки

Модель обучается на 16-32 объектах. Loss должен заметно уменьшаться. Если этого не происходит, ищем ошибку в данных, модели или optimizer.

### Тест 3. Короткий запуск

Запускаем 1-2 эпохи на части train и проверяем:

- скорость;
- расход GPU-памяти;
- сохранение checkpoint;
- расчёт validation MAE;
- загрузку сохранённой модели.

Только после этих проверок запускаем полное обучение.

## 13. Этап 10. Стратегия экспериментов

Рекомендуемый порядок:

1. Median baseline.
2. Mass baseline.
3. TF-IDF + mass.
4. Image encoder + mass.
5. Text encoder + mass.
6. Image + text + mass с замороженными encoders.
7. Разморозка последних блоков image encoder.
8. Разморозка последних блоков text encoder, если это оправдано.
9. Сравнение прямого target и энергетической плотности.
10. Настройка аугментаций и learning rate.

Для каждого эксперимента фиксируем:

- название;
- конфигурацию;
- seed;
- использованные признаки;
- число обучаемых параметров;
- validation MAE;
- лучшую эпоху;
- время обучения;
- путь к checkpoint;
- краткий вывод.

Новая сложность добавляется только тогда, когда предыдущий эксперимент работает корректно.

## 14. Этап 11. Итоговая оценка на test

После выбора лучшей конфигурации:

1. Загружаем лучший checkpoint.
2. Запускаем инференс на официальном test.
3. Считаем итоговый MAE.
4. Дополнительно считаем RMSE и распределение абсолютных ошибок.
5. Сохраняем предсказания в таблицу.

Полезные дополнительные показатели:

- доля прогнозов с ошибкой меньше 25 ккал;
- доля прогнозов с ошибкой меньше 50 ккал;
- доля прогнозов с ошибкой меньше 100 ккал.

Главный критерий успеха:

```text
test MAE < 50
```

## 15. Этап 12. Анализ пяти самых больших ошибок

Для пяти блюд с максимальной абсолютной ошибкой показываем:

- фотографию;
- список ингредиентов;
- массу;
- истинную калорийность;
- предсказание;
- абсолютную ошибку.

Возможные причины ошибок:

- необычный размер порции;
- масло или соус не видны на фотографии;
- список ингредиентов не содержит их количества;
- редкий ингредиент;
- сложное смешанное блюдо;
- плохое качество изображения;
- некорректная масса;
- ошибка разметки.

По итогам формулируем конкретные гипотезы улучшения модели.
