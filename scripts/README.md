# Модуль подготовки данных

Файл `dataset.py` отвечает за загрузку таблиц и изображений, подготовку признаков, разделение данных и создание объектов `Dataset` и `DataLoader` для PyTorch.

Главная задача модуля - гарантировать, что каждой фотографии соответствуют правильные ингредиенты, масса и калорийность.

## Общая схема

```text
dish.csv + ingredients.csv + images/
                  |
                  v
       load_and_prepare_data()
                  |
                  v
            общая таблица
                  |
                  v
          split_dataframe()
                  |
        +---------+---------+
        |         |         |
      train  validation    test
        |         |         |
        v         v         v
             DishDataset
                  |
                  v
          create_dataloaders()
                  |
                  v
       batches для обучения модели
```

## Константы обязательных столбцов

### `REQUIRED_DISH_COLUMNS`

Содержит названия столбцов, которые должны присутствовать в `dish.csv`:

- `dish_id`;
- `total_calories`;
- `total_mass`;
- `ingredients`;
- `split`.

Если хотя бы одного столбца нет, дальнейшая обработка останавливается с понятной ошибкой.

### `REQUIRED_INGREDIENT_COLUMNS`

Содержит обязательные столбцы справочника `ingredients.csv`:

- `id`;
- `ingr`.

## `ingredient_id_to_code()`

```python
ingredient_id_to_code(122)
```

Результат:

```text
ingr_0000000122
```

### Зачем нужна

В `ingredients.csv` идентификатор хранится как число, а в `dish.csv` используется строка специального формата. Функция приводит числовой ID к формату, по которому можно связать две таблицы.

## `load_and_prepare_data()`

Главная функция первичной подготовки данных.

### Что принимает

- `data_dir` - путь к папке `data`;
- `check_images` - нужно ли проверять наличие всех фотографий.

### Что делает

1. Проверяет наличие `dish.csv`, `ingredients.csv` и папки `images`.
2. Загружает обе таблицы через Pandas.
3. Проверяет обязательные столбцы.
4. Проверяет дубликаты `dish_id`.
5. Проверяет значения `split`.
6. Проверяет массу и калорийность на недопустимые отрицательные значения.
7. Создаёт словарь соответствия ID и названия ингредиента.
8. Преобразует технические ID в понятный текст.
9. Подсчитывает количество ингредиентов.
10. Формирует путь к фотографии каждого блюда.
11. При необходимости проверяет существование фотографий.

### Какие столбцы добавляет

| Столбец | Содержание |
|---|---|
| `ingredient_text` | Названия ингредиентов через запятую |
| `ingredient_count` | Количество ингредиентов блюда |
| `image_path` | Путь к `rgb.png` |

### Что возвращает

Один `DataFrame`, содержащий исходные и подготовленные признаки.

### Вложенная функция `decode_ingredients()`

Функция используется только внутри `load_and_prepare_data()`.

Она:

- разделяет строку ингредиентов по `;`;
- удаляет пустые элементы;
- проверяет наличие каждого ID в справочнике;
- заменяет ID названием продукта;
- объединяет названия через запятую.

Пример:

```text
ingr_0000000122;ingr_0000000026
```

превращается в:

```text
garlic, white rice
```

## `split_dataframe()`

Разделяет данные на три части:

- train;
- validation;
- официальный test.

### Почему нужен validation

Train используется для обновления весов модели. Validation используется для выбора архитектуры, learning rate и лучшей эпохи. Официальный test используется только для итоговой оценки.

Если подбирать параметры по test, итоговая метрика перестанет быть честной.

### Стратификация для регрессии

Обычная стратификация работает с классами, а в проекте решается задача регрессии. Поэтому значения `total_calories` предварительно делятся на десять интервалов через `pd.qcut()`.

Затем `train_test_split()` старается сохранить похожее количество объектов из каждого интервала в train и validation.

### Роль seed

Параметр `seed` обеспечивает воспроизводимость. При одинаковом seed объекты каждый раз попадают в одинаковые части выборки.

## `get_train_transforms()`

Создаёт преобразования изображений для train.

### Преобразования

- `Resize` приводит изображения к размеру 224 x 224;
- `HorizontalFlip` случайно отражает изображение;
- `ColorJitter` немного изменяет яркость, контраст и цвет;
- `Normalize` применяет статистики ImageNet;
- `ToTensorV2` преобразует изображение в PyTorch tensor.

### Зачем нужны аугментации

Датасет содержит только 2755 исходных train-объектов. Небольшие случайные изменения изображений помогают уменьшить переобучение и учат модель выделять устойчивые признаки блюда.

## `get_validation_transforms()`

Создаёт преобразования для validation и test.

В них нет случайных аугментаций. Каждое изображение обрабатывается одинаково, поэтому метрика остаётся стабильной и воспроизводимой.

## `DishDataset`

Класс связывает одну строку таблицы с фотографией и преобразует данные в формат PyTorch.

### `__init__()`

Сохраняет:

- подготовленный `DataFrame`;
- преобразования изображений;
- среднюю массу train;
- стандартное отклонение массы train.

Статистики массы передаются в dataset, чтобы одинаково нормализовать train, validation и test.

### `__len__()`

Возвращает количество блюд в выборке.

Эта функция позволяет PyTorch определить длину датасета.

### `__getitem__()`

Загружает один объект по его индексу.

Последовательность работы:

1. Получает строку из таблицы.
2. Открывает фотографию.
3. Преобразует её в RGB.
4. Применяет transforms.
5. Нормализует массу.
6. Создаёт tensor для массы и target.
7. Возвращает словарь признаков.

### Возвращаемый словарь

| Ключ | Содержание |
|---|---|
| `image` | Tensor изображения `[3, 224, 224]` |
| `text` | Строка с названиями ингредиентов |
| `mass` | Нормализованная масса `[1]` |
| `raw_mass` | Исходная масса в граммах |
| `target` | Настоящая калорийность |
| `dish_id` | Идентификатор блюда |
| `image_path` | Путь к фотографии |

### Нормализация массы

Используется формула:

```text
normalized_mass = (mass - mass_mean) / mass_std
```

После нормализации значения имеют удобный для нейросети масштаб. Статистики вычисляются только по train, чтобы информация из validation и test не влияла на обучение.

## `seed_worker()`

Устанавливает seed для каждого процесса DataLoader.

Это требуется при использовании нескольких workers. Без отдельной настройки случайные аугментации могут воспроизводиться непредсказуемо.

Функция синхронизирует генераторы NumPy и стандартного модуля `random` с seed PyTorch.

## `create_dataloaders()`

Объединяет все предыдущие шаги и создаёт готовые DataLoader.

### Что делает

1. Вызывает `split_dataframe()`.
2. Вычисляет среднюю массу и стандартное отклонение только по train.
3. Создаёт отдельный `DishDataset` для каждой части.
4. Назначает train-аугментации только обучающей выборке.
5. Настраивает воспроизводимый генератор случайных чисел.
6. Включает `pin_memory`, если доступна CUDA.
7. Создаёт train, validation и test DataLoader.

### Почему `shuffle=True` только для train

При обучении порядок объектов перемешивается, чтобы модель не запоминала последовательность данных. Для validation и test перемешивание не требуется, поскольку веса модели там не обновляются.

### Почему `num_workers=0`

Это безопасное начальное значение для Windows и Jupyter. После проверки пайплайна можно попробовать `num_workers=2` и сравнить скорость загрузки.

### Что возвращает

Функция возвращает три словаря.

#### `loaders`

```python
{
    "train": train_loader,
    "validation": validation_loader,
    "test": test_loader,
}
```

#### `dataframes`

Содержит таблицы с объектами каждой выборки. Они понадобятся для EDA и анализа ошибок.

#### `statistics`

```python
{
    "mass_mean": mass_mean,
    "mass_std": mass_std,
}
```

Эти значения нужно сохранить вместе с конфигурацией модели и использовать при будущем инференсе.

## Проверка результата

После создания DataLoader первый batch должен иметь примерно такие формы:

```text
image:  [4, 3, 224, 224]
mass:   [4, 1]
target: [4]
```

Это означает:

- batch содержит четыре блюда;
- изображение имеет три цветовых канала;
- каждое изображение имеет размер 224 x 224;
- для блюда используется один числовой признак массы;
- каждому блюду соответствует одно значение калорийности.

Текст пока остаётся обычной строкой. Он будет преобразован в токены после выбора text encoder.

## Почему модуль отделён от ноутбука

Вынос подготовки данных в `dataset.py` даёт несколько преимуществ:

- один код используется при обучении и инференсе;
- уменьшается риск разных правил обработки train и test;
- функции можно отдельно проверять;
- ноутбук остаётся коротким и читаемым;
- эксперимент можно воспроизвести повторным вызовом функций.
